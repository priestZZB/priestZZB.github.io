作为计算机专业生，不管是课程设计、团队项目还是实习，Git都是必须掌握的版本控制工具。很多同学只会用`git add`、`git commit`、`git push`三个基础命令，遇到代码冲突、分支切换、版本回滚就慌了。分享我总结的**Git常用命令+实用分支管理策略**，新手也能轻松上手。

### 一、日常开发必用的10个Git命令（覆盖90%场景）
1. 基础提交：`git add .` → `git commit -m "feat: 新增用户接口"` → `git push origin 分支名`
2. 分支操作：`git branch`（查看分支）→ `git branch 分支名`（创建分支）→ `git switch 分支名`（切换分支）→ `git branch -d 分支名`（删除分支）
3. 拉取远程代码：`git pull origin 分支名`（开发前必做）
4. 查看日志：`git log`（按q退出）

### 二、新手必学的分支管理策略（适合学生/小团队）
不用追求复杂的GitFlow，核心分4个分支即可：
1. **main/master**：主分支，存放可上线的稳定代码，禁止直接开发。
2. **dev**：开发分支，团队所有人的代码合并到这里。
3. **feature/xxx**：功能分支（如feature/user-login），开发完成后合并到dev。
4. **bugfix/xxx**：bug修复分支（如bugfix/login-null），修复后合并到dev。

### 三、如何处理代码冲突？
代码冲突大多是多人修改同一文件的同一行代码导致，解决步骤：
1. 执行`git pull`发现冲突，IDEA会提示“Conflict”，打开冲突文件，会看到`<<<<<<<`、`=======`、`>>>>>>>`标记。
2. 和队友沟通，保留正确代码，删除冲突标记和无用代码。
3. 解决后执行：`git add 冲突文件名` → `git commit -m "fix: 解决代码冲突"` → `git push`。

### 核心原则
**一个分支只做一件事**，不要在一个分支上同时开发多个功能；每次开发前先拉取远程代码，提交信息要规范（如feat/fix/docs: 描述）。

### 总结
Git的核心是“版本控制和协作”，命令只是工具，关键是掌握分支管理的思路。新手先把以上内容用熟，遇到问题不要慌，大部分问题都能通过简单命令解决。
